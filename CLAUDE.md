## Commands

```bash
npm install                      # install deps
npx expo start --web             # dev server, web target (fastest loop)
npx expo start                   # dev server, native (scan QR with Expo Go)

npm run typecheck                # tsc --noEmit
npm run lint                     # expo lint
npm run format                   # prettier --write .
npm run format:check

npm test                         # jest, full suite
npm test -- lib/simulate.test.ts # single file
npm test -- -t "test name"       # by test name
npm test -- --ci                 # matches CI invocation
```

Route types (`expo-env.d.ts`, `.expo/types/*.d.ts`) are gitignored and normally generated by
`expo start`. Without a dev server running (e.g. before a typecheck in CI or a fresh clone), run
`npx expo customize tsconfig.json` first — this is the documented no-dev-server equivalent and is
exactly what `.github/workflows/ci.yml` does before typecheck/lint/test.

Building:

```bash
eas build --profile development|preview|production --platform android|ios
```

`eas.json`'s `preview`/`production` profiles set `SENTRY_DISABLE_AUTO_UPLOAD=true` — no
`SENTRY_AUTH_TOKEN` is configured yet, so the Sentry Gradle plugin's sourcemap-upload step would
otherwise fail the build. Crash *reporting* still works without it; only readable (non-minified)
stack traces in Sentry require setting up the token later.

Web SEO/meta-tag changes must be verified with a real export, not just the dev server — the dev
server doesn't apply the same HTML template:

```bash
npx expo export --platform web --output-dir <tmp-dir>
```

## Environment

`.env` (gitignored) needs `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` —
`lib/supabase.ts` throws at import time if either is missing. `EXPO_PUBLIC_SENTRY_DSN` is optional;
`lib/crash-reporter.ts` stays a console-only no-op without it.

## Architecture

**Data flow is three layers, always in this order:** `lib/data/*.ts` (thin Supabase query
functions, one file per table) → `hooks/use*.ts` (wraps a query in `hooks/useAsync.ts`) → screen
component. `useAsync` is the single fetch/loading/error/refetch primitive every data hook shares —
it also refetches automatically on screen focus (via expo-router's `useFocusEffect`), which is
what makes e.g. Home's net worth update after logging a transaction in the modal without a manual
reload. Any new data-backed screen should go through this chain rather than calling Supabase
directly from a component.

**Auth and routing are coupled in `app/_layout.tsx`.** `AuthProvider` (`lib/auth-context.tsx`)
exposes `session`/`profile`/`signIn`/`signUp`/`signOut`/`deleteAccount`. The root `Stack` uses
`Stack.Protected` guards keyed off `!session` / `!!session && !onboarded` / `!!session &&
onboarded` to route between the `(auth)` group, `/onboarding`, and `(tabs)` + modal screens —
there's no separate route-guard middleware, it's entirely these three guard conditions.

**Every user-owned table has Postgres RLS scoped to `auth.uid()`** (`supabase/migrations/`).
Account deletion (`0002_delete_own_account.sql`) is a `security definer` RPC, not a client-side
`auth.admin` call — the anon/publishable key can never delete arbitrary users, only the caller's
own row, and every owned table cascades from `auth.users` on delete.

**Design tokens flow one direction:** `constants/theme.ts` (colors, spacing, radius, motion
timings) → `hooks/useTheme.tsx`'s `PrefsProvider` (resolves light/dark, currency, haptics) →
`components/ui/*` primitives via `useTheme()`. Reduced motion is OS-level only (`useReducedMotion`
from Reanimated) — there is no in-app override toggle.

**`hooks/useMotion.ts` is the only place animations are constructed.** `enter`/`enterList` for
screen/list entrances, `toSpring`/`toTiming` for value animations. Default spring config is
`motion.springSoft` (critically damped, no overshoot) — deliberately not `motion.springBouncy`,
which was removed. Don't reach for `withSpring`/`withTiming` directly in a screen; go through this
hook so reduced-motion handling stays centralized.

**Two unrelated icon systems, don't conflate them:**
- In-app UI icons: `scripts/generate-icons.mjs` fetches SVGs from the Iconify API into
  `assets/icons/lucide/`, `react-native-svg-transformer` turns them into components at bundle
  time, `lib/lucide-icons.tsx` re-exports them with a `size` prop shim.
- DB-stored icon keys: `goals.icon` / `achievements.icon` store a kebab-case string
  (`"piggy-bank"`), and `lib/icons.ts`'s `ICON_BY_KEY` map resolves that string back to a
  component. Adding a new goal/achievement icon means adding it to both this map and wherever the
  kebab-case key is written.

**`data/seed.ts` is mixed — most of it is live, some of it is dead.** `CATEGORIES`/`CATEGORY_MAP`,
`PERSONAS`, `GOALS` (onboarding + New Goal presets), and `PROFILE` (Simulator's baseline
coffee/subscription numbers) are all still read at runtime. `INSIGHTS` is not — real insights come
from `lib/aggregate.ts`'s `computeBudgetInsights`, computed from actual transaction data.

**Web output mode is `"single"` (SPA), not `"static"`** (`app.json`). This means `app/+html.tsx`
has no effect — expo-router's static-render document override only applies under `"static"`
output. Web `<head>` meta tags (SEO, Open Graph, theme-color) live in `public/index.html`, a
project-owned template scaffolded via `npx expo customize "public/index.html"`, which Metro copies
verbatim into the web build root.

**Platform split for the one DOM-only dependency:** `motion` (motiondivision) has no React Native
renderer and is used in exactly one file, `components/device-frame/DeviceFrame.web.tsx` (the
`.web.tsx` extension resolves it out on native via Metro's platform extension). Every other
animation in the app runs on Reanimated 4, which works on both native and web — don't add a second
`motion`-based animation path.

## Testing

`jest-expo` preset, tests live next to their source as `*.test.ts(x)` (not in a `__tests__`
directory). SVG imports are mocked via `__mocks__/svgMock.js`. `lib/simulate.ts` and
`lib/aggregate.ts` are pure functions with no React/Supabase dependency — prefer testing new
business logic there rather than through a component.
